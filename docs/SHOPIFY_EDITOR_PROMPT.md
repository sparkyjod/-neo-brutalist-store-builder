## The Prompt

Act as a senior Shopify theme engineer and full-stack developer. Upgrade this Neo-Brutalist Store Builder so editing a store feels exactly like Shopify's theme customizer and Online Store admin, and make its technical CORE visible and understandable inside the app itself. Keep the Neo-Brutalist identity (thick black borders, hard shadows, solid vibrant colors, Archivo Black / Space Grotesk / DM Sans) and keep every existing working feature: storefront, cart/checkout with discount codes, product/order/customer admin, autosave, undo/redo, draft vs published, 3 theme presets.

### 1. Shopify-style editing experience (must all be real, no decorative controls)
- Theme Editor opens on the homepage by default, with a page/template selector at the top (Home, Shop, Product, Cart, About, FAQ, Contact) — switching templates switches the editable section list and preview for that page.
- Left panel = section tree for the selected template, in render order: drag-and-drop reorder, add section, duplicate, delete, show/hide, expand to reveal blocks inside a section.
- Blocks inside sections (e.g. a testimonial inside Testimonials, a slide inside Hero, a link inside Footer columns) are individually selectable, editable, reorderable, duplicable and deletable — like Shopify blocks.
- Center = live preview of the selected template; clicking anything selects it and scrolls the right panel to its settings; selection outline is always visible; desktop / tablet / mobile width toggle.
- Right panel = settings for the selection only, grouped like Shopify (Content, Style, Layout), using the right input for each value: text fields, rich text, color swatches + hex, range sliders with numeric readout, toggles, dropdowns, image/glyph pickers.
- Inline editing: double-clicking a heading or paragraph in the preview turns it into an editable text field in place; Enter/blur saves to draft and autosaves.
- Header bar of the editor: store name + template name, Draft / Published status badge, Undo, Redo, Save (with saved-at timestamp), Preview (opens storefront as a customer), Publish, and a "…" menu with Rename theme, Duplicate theme, Reset to preset.
- Every change autosaves to the DRAFT only; the live storefront keeps showing the PUBLISHED version until Publish is pressed. Show a clear "Unpublished changes" indicator when draft ≠ published.
- Add Section library is searchable, grouped (Heroes, Products, Content, Social proof, Conversion), and each entry shows a one-line plain-English description of what it does.

### 2. Add the CORE — a Frontend / Backend explainer built into Admin
Add a new Admin page called "Core" (nav item between Dashboard and Products) that teaches the owner how their store works, using their own live store data:

**Frontend card (what customers see and touch):**
- Plain-English meaning: "The Frontend is everything a visitor sees in the browser — your storefront pages, theme, colors, fonts, sections, product cards, cart drawer and checkout form. If it has a color, a font, or a position on the page, it is Frontend."
- List what lives in the Frontend of THIS app: Storefront templates, Theme settings, Section & block settings, Editor preview — each with a button that jumps to where you edit it (Editor / Themes).
- Show live values from the current theme: store name, primary color, heading font, number of sections on the homepage, published or draft status.

**Backend card (the engine customers never see):**
- Plain-English meaning: "The Backend is the server and database behind the store. It stores products, prices, stock, orders and customers, checks discount codes, decrements stock when an order is placed, saves your draft, and serves the published version. Customers never see it, but every page they load and every order they place runs through it."
- List what lives in the Backend of THIS app: Product catalog data, Orders & payments status, Customers, Draft vs Published store config, Theme presets & saved themes — each with a button that jumps to the matching Admin page.
- Show live counts from the database: total products, total orders, total customers, total revenue, draft last-saved time, published status.

**How they talk to each other (diagram row):**
- A simple 3-step visual: Customer (Frontend) → Request → Backend (database) → Response → updated Frontend. One sentence per step, e.g. "You press Publish in the Frontend editor → the Backend saves the draft as the published config → every visitor's Frontend now renders the new version."

**Rule for the Core page:** all numbers and theme values must come from the real store data (the same bootstrap data the rest of Admin uses) — no hard-coded example numbers.
